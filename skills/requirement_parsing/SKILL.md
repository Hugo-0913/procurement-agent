# 采购需求解析

## 适用时机

主 Agent 收到自然语言采购需求，进入 `PARSING` 阶段时加载本技能。

## 必须产出的字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `material_name` | 是 | 物料名称，保留用户原始表述，不擅自归一化 |
| `quantity` | 是 | 数量，整数 |
| `unit` | 否 | 单位，用户未说明时留空，不猜测 |
| `expected_date` | 否 | 期望到货日期，ISO 格式 |
| `budget` | 否 | 预算上限，数值 |
| `cost_center` | 否 | 成本中心编码 |
| `note` | 否 | 其他约束，例如"优先 A 类供应商" |

## 解析规则

1. 只提取用户明确表达的信息，禁止补全未提及的字段。
2. `material_name` 与 `quantity` 缺任意一项时，不得继续推进流程，必须向用户提出澄清问题。
3. 相对时间表达按当前日期换算：本周、下周、明天等需转换为具体日期。
4. 数量与单位分离解析，例如"50 箱 A4 纸"解析为 `quantity=50`、`unit=箱`、`material_name=A4 纸`。
5. 预算出现"不超过""控制在"等表述时按上限处理。

## 输出格式

必须输出单个 JSON 对象，字段名与上表一致，缺失的可选字段用 `null`。

```json
{
  "material_name": "A4 纸",
  "quantity": 50,
  "unit": "箱",
  "expected_date": "2026-09-21",
  "budget": 1200,
  "cost_center": "CC-1001",
  "note": null
}
```

## 常见错误

- 把"下周一"直接当字符串输出而不换算为日期。
- 用户说"再来点纸"时猜测数量——此类需求必须澄清。
- 把备注中的供应商偏好误当成预算字段。
