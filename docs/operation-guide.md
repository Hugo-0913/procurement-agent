# 上手操作手册

这份文档解决一件事：**你自己能把它跑起来、点一遍、并把每一步讲清楚**。不需要背，照着做两次就熟了。

## 一、启动与停止

```powershell
# 启动（必须在项目根目录，必须用 .venv 里的解释器）
cd D:\桌面\Agent
.\.venv\Scripts\python.exe -m uvicorn procurement_agent.web.app:create_app --factory --port 8000

# 打开
http://127.0.0.1:8000
```

三个要点：目录必须是 `D:\桌面\Agent`（配置和技能按相对路径读）；解释器必须是 `.venv` 里的；启动窗口不能关，关了服务就停。

**模型模式是自动判断的**：配了 `DEEPSEEK_API_KEY`（在 `.env` 里）就用真实模型；没配就自动用内置规则解析器，页面顶部会显示橙色"离线演示模式"横幅。演示前确认一下横幅在不在，免得临场解释不清。

停止：在启动窗口按 Ctrl+C。

## 二、四个页面各能做什么

| 页面 | 路径 | 能做什么 |
| --- | --- | --- |
| 任务看板 | `/` | 提交新采购需求、按状态筛选历史任务、点卡片进入执行页 |
| 采购执行页 | `/tasks/{id}` | 看三栏：左侧上下文与技能状态、中间任务树、右侧时间线；审批卡片也在这里弹出 |
| 数据台 | `/data` | 查供应商/报价/订单；**三个故障注入开关**在右上角 |
| 评测页 | `/eval` | 一键跑 30 条用例，看成功率、人工介入率、token 成本、失败用例 |

## 三、五个演示场景（照做即可）

**场景 1 · 正常采购**

看板页点「填入示例需求」→ 提交。执行页停留观察：左侧四个技能标签从虚线「仅描述」逐个变实心「已加载全文」；中间任务树展开三个子 Agent；右侧时间线里中间件动作单独标记。

讲什么：技能是渐进式加载的，主 Agent 一开始只知道技能名和描述。子 Agent 通过框架的 `task` 工具被委派——时间线里每条 `框架委派成功` 都是模型真实发起的工具调用，不是我在代码里记账。

**场景 2 · 报价最低的供应商资质临期**

数据台打开「让供应商 B 资质过期」→ 回看板提交 `采购 50 箱 A4 纸`。看比价结论。

讲什么：系统没有选最便宜的那家，因为它资质临期，改选了次优并把原因写进结论。这个理由是按规则生成的，不是模板。

**场景 3 · 超预算触发审批并批准**

提交 `采购 3000 箱 A4 纸`。橙色审批卡片出现 → 点「批准」。

讲什么：审批是持久化中断——任务挂起期间服务重启，它仍然在等待审批，批准后从断点继续。审批通过前订单不写库。

**场景 4 · 驳回重跑**

再提交一次 `采购 3000 箱 A4 纸` → 点「驳回」并填理由。观察任务树里比价委派出现第二次。

讲什么：驳回不是终止任务，而是带着理由回退到比价阶段重跑。

**场景 5 · 交期不可行 / 唯一供应商**

提交 `紧急采购 3000 箱 A4 纸，明天必须到货` → 审批卡片上会出现两条规则，第二条是交期不可行。

再把「让供应商 B 资质过期」和「让供应商 C 停止报价」同时打开，提交 `采购 50 箱 A4 纸` → 只剩一家能供货，系统转人工而不是直接失败。

**场景 6 · 模糊需求**

提交 `帮我买点办公用纸`。任务停在解析阶段提问，子 Agent 一次都没被委派。

讲什么：系统宁可停下来问，也不猜数量。这条路径是确定性代码，不依赖模型自觉。

**收尾 · 指标**

评测页点「运行评测」。指标全部来自这 30 条固定用例，可复现。

## 四、出问题怎么查

| 现象 | 原因与处理 |
| --- | --- |
| 网页打不开 | 服务没启动或窗口被关了；重新启动 |
| 提交需求后任务直接失败 | 配了 key 但 key 无效／网络不通；看执行页时间线里的红字错误 |
| 页面一直停在"需求解析" | 真实模型模式下首次调用较慢（约 5-8 秒），等一下；超过 30 秒看时间线是否有重试记录 |
| 审批卡片不出现 | 金额没超 ¥50,000；用 `采购 3000 箱 A4 纸` |
| 技能标签一直是"仅描述" | 该阶段还没走到；走到由比价阶段时会点亮 |
| 离线模式下数量识别不对 | 规则解析器要求写清数量与单位，例如 `采购 50 箱 A4 纸` |

## 五、面试追问速查

**为什么状态机在外层？** 状态要跨进程存活、要在审批处挂起、要被页面查询，框架的会话内规划承担不了这三件事。

**框架的 task 委派用上了吗？** 用上了。每个阶段主 Agent 通过 `task` 工具把工作交给子 Agent，事件里标 `framework`；模型没委派时会降级并标 `fallback`，不伪装。

**业务判断为什么不用模型？** 资质过期是日期比较，比价是成本公式，可测可复现。模型只用在真正需要语义理解的地方——把"下周一"变成日期。

**一次任务花多少资源？** 真实模型下约 20-28 秒、4.5-5.8 万 token，主要是框架提示词与 7 次模型调用的开销。这个数字是采集模型返回的真实用量得到的，不是估算。

**如果模型输出坏 JSON？** 按可重试错误处理并带修正动作重试，上限 3 次；耗尽则任务失败并保留完整上下文，不让流程带病继续。

**怎么变成生产系统？** 差距不在 Agent，而在真实数据源、企业 SSO 与权限矩阵、容器级隔离与审计日志。`docs/sandbox-security.md` 里有逐条演进方案与代价。
