# 交接说明

> 给下一个会话（或下一个人）看的现状说明。读完这份再看 `PRD.md` 与 `docs/decision-log.md` 即可接手。

## 1. 这是什么

**医用耗材采购自动化 Agent**，基于 DeepAgents 的多 Agent 系统。
用户用自然语言或点选式表单提出采购需求，系统完成「需求解析 → 资质核验 → 逐项比价 → 订单生成」，
遇到敏感情况停下来让人审批。

**项目性质：求职作品**，目标岗位 AI/Agent 应用开发。业务是外壳，工程内核（委派架构、状态机、
治理与可观测、可复现评测）才是价值所在。

## 2. 怎么跑起来

```powershell
cd D:\桌面\Agent
.\.venv\Scripts\python.exe -m uvicorn procurement_agent.web.app:create_app --factory --port 8000
```

打开 http://127.0.0.1:8000 。顶栏右上角显示当前是**真实模型**还是**离线演示模式**。

两个坑：

- **必须在项目根目录启动**，配置与技能按相对路径读取。
- **启动需要 6～20 秒**（Python 冷启动），期间访问会"连接被拒绝"，别误判成启动失败。

模型密钥在 `.env`（已 gitignore）；没配 key 时自动降级为内置规则解析器，功能完整可演示。

## 3. 用户明确表达过的偏好（重要）

1. **面向用户视角**：页面只展示业务人员看得懂的内容，不要堆技术字段。
2. **非必要不要问**：方向明确就自己往下做；但**领域边界类的问题必须问**（见教训第 5 条）。
3. **数据少而清晰**：「数据要合理清晰，不追求大量」——2 种物料、4 家供应商就够，但每家都有演示用途。
4. **演示要能用**：改了前端必须保证用户刷新后真的能用，不接受"代码看起来对"。

## 4. 系统功能

四个页面：

| 页面 | 路径 | 内容 |
| --- | --- | --- |
| 任务看板 | `/` | 「选着买」点选式表单 + 「说着买」自然语言；历史任务列表与状态筛选 |
| 采购执行页 | `/tasks/{id}` | 三栏：左侧上下文与技能状态、中间任务树、右侧时间线；澄清/审批卡片在独立容器里 |
| 数据台 | `/data` | 「供应商能不能用」（含不能用的原因）、「我的订单」；右上角三个异常模拟开关 |
| 评测页 | `/eval` | 一键跑 30 条用例，出成功率、人工介入率、耗时、token、委派次数 |

两条下单路径是**刻意区分**的：点选式跳过模型解析（技能状态里"需求解析"保持虚线、
解析工具调用 0 次），自然语言走完整模型链路。

## 5. 业务规则（都是确定性的，不交给模型）

资质核验：黑名单 → 资质缺失 → **经营范围不覆盖** → **缺产品注册证** → 资质过期 → 临期标记。
全部**逐物料判定**（经营范围与注册证都是按物料查的）。

比价：综合成本 = 单价 × 数量 + 运费；推荐排序按「资质临期 → 交期不满足 → 效期不足 → 未达起订量 → 综合成本」。

审批五条规则：合计金额超阈值、供应商资质临期、非最低价且差额超 10%、交期不可行、报价不足；
另有起订量与效期两条转人工规则。

## 6. 演示数据（`src/procurement_agent/db/seed.py`，改业务域只改这一处）

| 供应商 | 设定 | 演示的规则 |
| --- | --- | --- |
| 华康医疗器械 | 资质齐全 A 类 | 正常路径与中选 |
| 瑞康医械供应链 | 资质齐全 B 类、单价最低 | 正常中选 |

物料：一次性无菌注射器（100 支/箱）、医用外科口罩（50 只/盒），均带别名与效期要求。

## 8. 已知局限（面试可主动讲）

- **虚拟文件系统与沙箱层二**已实现并有测试，但业务流程里没有真实调用点（能力为扩展预留）。
- **成本中心的 `budget` 字段**只解析不参与预算校验，没有"预算还剩多少"的管控。
- **并发未压测**：SQLite 写锁与检查点连接共享在真并发下表现未知。
- **多物料**已支持，但**没有分批到货、没有阶梯价**（现在是单一单价）。
- **没有登录与权限体系**，审批人身份是页面填的。

## 9. 踩过的坑（避免重犯）

1. **静态资源缓存**：改了 JS 浏览器仍用旧文件，表现为"按钮点了没反应"。现在静态资源带版本号
   （`app.py` 的 `ASSET_VERSION`，**每次改前端都要更新它**）并禁用强缓存。
2. **待办卡片被时间线重绘抹掉**：卡片曾插在 `#timeline` 内，而时间线每 5 秒整体重绘，
   导致澄清框"输不进字"。现在卡片放在独立的 `#action-cards` 容器，并有结构测试钉住。
3. **逐物料规则必须逐物料执行**：经营范围与注册证按物料判定，但流程最初只拿第一个物料的 ID 跑一次，
   多物料订单的第二种物料判定是错的。
4. **澄清补充是"修正"不是"追加"**：早期把补充说明追加到原文末尾，原文里的错误物料仍在，
   模型继续按错的解析，任务永远卡住。现在只保留最新一条，并在提示词里声明补充说明优先。
5. **领域边界要问清，不能用默认值代替**：最初按"耗材"理解做了办公用品，
   后来才发现需求方要的是医用耗材，导致 205 处替换。
6. **测试替身必须与真实对象类型一致**：替身返回字符串而真实模型返回 `AIMessage`，
   导致 `json.loads` 在真机才崩。现在替身直接复用 `OfflineChatModel`。
7. **改完先跑测试再上真机**：跳过测试直接真机验证过，被一个提示词格式化错误拦住了（测试本能秒杀）。

## 10. 常用定位

```powershell
# 起服务（后台隐藏窗口 + 日志）
Start-Process -FilePath ".\.venv\Scripts\python.exe" `
  -ArgumentList "-m","uvicorn","procurement_agent.web.app:create_app","--factory","--port","8000" `
  -WorkingDirectory "D:\桌面\Agent" -WindowStyle Hidden `
  -RedirectStandardOutput ".\uvicorn.out.log" -RedirectStandardError ".\uvicorn.err.log"

# 停服务
netstat -ano | Select-String ":8000" | Select-String "LISTENING"   # 拿到 PID 后 Stop-Process -Id <PID>

# 看数据库里有什么
.\.venv\Scripts\python.exe -c "import sqlite3;c=sqlite3.connect('data/procurement.db');print([r for r in c.execute(\"select name from sqlite_master where type='table'\")])"
```

关键文件：`agents/delegation.py`（框架委派与能力工具）、`state/graph.py`（流程编排）、
`agents/coordinator.py`（阶段处理器）、`sandbox/policy.py`（审批规则）、`web/routes.py`（接口）。
